# Parent–student relationship management (first increment)

Preserves Figure 4.24 ParentStudentLink: linkId, parentId, userId, linkedDate, linkStatus. Parent and Student navigations are additions. Both foreign keys reference Users with restrictive deletion. One unique parentId/userId pair is retained through deactivation and reactivation. Original linkedDate is UTC and remains unchanged. UI dates are MYT.

Admin-only ParentStudentLinks controller lists, searches and filters relationships, creates links and confirms activation/deactivation. Parent is a relationship, not a required account role: any active User can be either the monitoring user (parentId) or the monitored user (userId), and can occupy both positions in different links. Both dropdowns contain the same eligible accounts. Legacy Parent-role accounts remain eligible for compatibility. Admin accounts, self-links, inactive accounts and duplicates are rejected. Writes require POST with antiforgery, validate only specific bound fields, and lock account rows in stable order in a serializable transaction. No account roles or personal financial records are changed. Status is Active or Inactive; there is no delete endpoint.

The missing Admin dashboard view is supplied with a relationship management entry. Admin sidebar shows only Admin Dashboard and Relationships. Non-admin navigation remains unchanged. No monitoring permissions are enabled by this increment: future monitoring must validate an Active link and both current account eligibility/statuses on every request. No notifications are sent yet.

Apply AddParentStudentLink locally with Update-Database before visiting these pages; apply a matching Azure migration before deployment. Generation does not update either application database. Login with an existing Admin account and open Dashboard/Admin -> Manage relationships. Registration creates ordinary User accounts, which need no conversion to become a parent in a relationship. An existing Admin still manages links; Admin provisioning is separate. No separate Parent login, dashboard or role switch is required.

Test ordinary User-to-User links, users in both positions across different relationships, duplicates, inactive accounts, original ID/date across deactivate/reactivate, multiple parents/students, confirmation, search/status/pagination, missing CSRF, and denied direct requests from User/Parent/anonymous sessions.
