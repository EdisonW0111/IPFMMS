# Monitoring alerts and notification management

Figure 4.24 Notification attributes preserved exactly: notificationId, userId, relatedUserId, notificationType, title, message, createdDateTime, isRead. Additional eventKey (SHA256 unique), linkId, requestVersion, sourceMonth support deduplication and consent. Three restrictive FKs: receiver User, optional related User, optional ParentStudentLink. Only Notifications table and its indexes are added.

Current Malaysia month only: BudgetOverspending when recorded category expenses through today exceed that category's saved fixed/percentage budget (percentage uses income through today). Equal-to-limit does not alert. Unbudgeted categories are not overspending alerts. LowFinancialHealth when all components are available and Overall <40 (the chosen Needs attention band). Current-month score alerts clearly say provisional. No score fabricated for insufficient data.

One first-observed budget alert per category/month/accepted request version, one low score alert per month/version. Alerts retain original evidence and point to the summary for latest data. Corrections/recovery do not delete or reset read state, and repeated requests/refreshes never duplicate events. New independently accepted request versions can receive fresh alerts. Account locks, serializable per-link transactions and unique eventKey protect concurrency. No financial, contribution, rollover, prediction or health-history writes. IDs use NTF.

In-app delivery: dashboard sidebar unread-count fetch checks current viewer's accepted links on initial load, once per minute while visible, and on returning to the tab. Notifications page also refreshes. No background job, external scheduling or email financial alerts. Sleeping Azure free apps catch up when a monitoring user opens the app. This does not promise immediate delivery while nobody is using it. Existing SMTP linking emails remain separate.

List/unread/mark-read queries scope receiver to claims and require the same Active, accepted, eligible link/version. Disconnected/inactive/unaccepted links receive no new alerts and previous financial alerts are hidden, including unread counts. A reconnect requires fresh acceptance and does not restore old-version alerts. Summary links independently reauthorize. Mark read/unread and mark all read are POST + CSRF, scoped to visible own notifications only. History/filter pagination uses 20 items. No Admin changes.

Apply AddMonitoringNotifications using Update-Database locally before testing; existing linking migrations are also required. Azure migration must precede eventual deployment. No application database is updated automatically by Codex. Test budget/score boundaries, no-data suppression, duplicate/concurrent refresh, directionality, multiple observers, read-state preservation, disconnection and version changes, ownership, CSRF, filter/pagination and mobile layout.
